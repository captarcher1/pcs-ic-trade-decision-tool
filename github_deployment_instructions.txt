TROUBLESHOOTING
----------------
"Unable to create '.git/index.lock': File exists"
  This project folder lives inside OneDrive, and OneDrive's background sync can
  occasionally leave a stale lock file behind after an interrupted git operation.
  Fix: close any other terminal/IDE that might be mid-git-operation, then delete
  the lock file and retry:
    Remove-Item .git\index.lock
    git status

Authentication errors on push (password no longer accepted)
  GitHub requires a Personal Access Token (PAT) or SSH key instead of your
  account password for git operations over HTTPS.
  - PAT: GitHub.com -> Settings -> Developer settings -> Personal access tokens
    -> generate one with "repo" scope, then use it in place of your password
    when prompted (or store it via `git credential-manager` / Windows Credential
    Manager so you're not prompted every time).
  - SSH: if you'd rather not deal with tokens, switch the remote to SSH:
      git remote set-url origin git@github.com:captarcher1/pcs-ic-trade-decision-tool.git
    (requires an SSH key already added to your GitHub account).

Nothing to commit / "working tree clean"
  Means git already sees these files as committed (e.g., if you committed them
  some other way already) — double check with `git log -3 --stat` to confirm
  the changes above are actually in the history.

Accidentally staged .env or venv/.venv
  Should not happen since .gitignore already lists them, but if `git status`
  ever shows .env staged, unstage it before committing:
    git restore --staged .env
